# ESP8266 手机串口信息传输文档

## 1. 文档定位

本文档描述当前仓库中已经实现的 `STM32F407` 小车手机日志同步方案。该方案的目标是：

- 保留电脑端串口调试能力
- 通过 `ATK-ESP8266` 将同一份日志同步显示到手机
- 不让 Wi-Fi 模块影响小车主业务流程

说明：

- 本方案仅用于文本日志转发
- 不包含 `OV2640` 图像采集与图像传输功能
- 手机端只负责查看日志，不负责控制小车

## 2. 当前工程实现状态

当前工程已经具备如下链路：

- `USART1`
  输出到板载 `CH340`，供电脑串口调试
- `USART3`
  连接 `ATK-ESP8266`，供手机接收日志
- `UartSend(...)`
  同时向 `USART1` 和 `ESP8266_SendLog(...)` 发送文本

对应文件如下：

- [main.c](../firmware/Core/Src/main.c)
- [esp8266.c](../firmware/Core/Src/esp8266.c)
- [esp8266.h](../firmware/Core/Inc/esp8266.h)
- [usart.c](../firmware/Core/Src/usart.c)
- [usart.h](../firmware/Core/Inc/usart.h)

当前主程序上电后会：

1. 初始化 `USART1`
2. 初始化 `USART3`
3. 调用 `ESP8266_Init()`
4. 在串口打印模块初始化结果
5. 在主循环中持续调用 `ESP8266_Poll()`

## 3. 硬件连接与跳线

### 3.1 模块连接方式

本实验不需要额外杜邦线，直接将 `ATK-ESP8266` 模块插在探索者开发板的 `ATK-MODULE` 接口上即可。

模块插接后，开发板会完成以下连接：

- 模块 `TXD` -> 开发板 `USART3_RX`
- 模块 `RXD` -> 开发板 `USART3_TX`
- 模块由 ATK 接口供电

### 3.2 跳线要求

开发板上的 `P2` 负责在以下用途之间切换：

- `COM3 / RS232`
- `ATK-MODULE`

当前方案必须满足：

- `P2` 切到 `ATK-MODULE`

如果 `P2` 没有切到 `ATK-MODULE`，即使代码已初始化 `USART3`，数据也不会送到 ESP8266。

### 3.3 串口分工

当前工程固定采用如下职责划分：

- `USART1`
  电脑端调试输出
- `USART3`
  ESP8266 AT 指令与日志发送

`USART3` 引脚为：

- `PB10 -> USART3_TX`
- `PB11 -> USART3_RX`

## 4. ESP8266 当前工作模式

### 4.1 模块工作模式

当前实现采用 `AP + TCP 服务器` 模式，固定参数如下：

- `SSID=ATK-ESP8266`
- `PASSWORD=12345678`
- `PORT=8086`
- 串口参数：`115200, 8, N, 1`

> 说明：以上是 ATK-ESP8266 模块的默认软 AP 参数，仅用于本地调试，不是个人路由器或账号密码。实际使用时建议修改 `firmware/Core/Src/esp8266.c` 中的 SSID 和密码。

这样配置的优点是：

- 不依赖路由器，演示更稳定
- 手机只需连接模块热点即可
- 模块初始化逻辑简单，方便答辩演示

### 4.2 当前初始化 AT 指令序列

当前代码中的初始化主流程为：

```text
AT
AT+RST
ATE0
AT+CWMODE=2
AT+CWSAP="ATK-ESP8266","12345678",1,4
AT+CIPMUX=1
AT+CIPSERVER=1,8086
```

其中：

- `AT`
  检查串口是否可通信
- `AT+RST`
  重启模块并重新同步
- `ATE0`
  尝试关闭回显，减少接收解析干扰
- `AT+CWMODE=2`
  设置为 `AP` 模式
- `AT+CWSAP=...`
  配置热点名称和密码
- `AT+CIPMUX=1`
  允许多连接
- `AT+CIPSERVER=1,8086`
  开启 TCP 服务器

如果初始化失败，程序不会卡死，而是记录失败阶段并继续运行主业务逻辑。

## 5. 手机连接方式

完成上面的初始化后，模块将工作为热点，默认 IP 为：

```text
192.168.4.1
```

手机端需要：

1. 连接 Wi-Fi 热点 `ATK-ESP8266`
2. 打开网络调试助手
3. 选择 `TCP Client`
4. 连接目标：

```text
IP: 192.168.4.1
PORT: 8086
```

连接成功后，手机即可接收 STM32 发出的文本日志。

## 6. 当前日志发送机制

### 6.1 双通道日志输出

当前主程序中的 `UartSend(const char *msg)` 已实现双通道输出：

```c
static void UartSend(const char *msg)
{
    HAL_UART_Transmit(&huart1, (uint8_t *)msg, strlen(msg), 1000);
    (void)ESP8266_SendLog(msg);
}
```

因此当前所有调用 `UartSend(...)` 的业务日志，都会：

- 同步输出到电脑端串口
- 尝试同步发送到手机端

### 6.2 建链检测

当前驱动通过以下方式维护手机连接状态：

- 解析模块上报的 `x,CONNECT`
- 解析模块上报的 `x,CLOSED`
- 轮询执行 `AT+CIPSTATUS`
- 维护当前活动连接号 `link_id`

因此日志发送并不固定死用 `ID0`，而是会优先尝试已知连接，再在 `0~4` 范围内尝试可用链路。

### 6.3 发送流程

当前发送一条日志时，执行流程为：

1. 若模块未初始化成功，则直接返回
2. 若当前未确认手机已连接，则先轮询连接状态
3. 若有可用连接，则发送：

```text
AT+CIPSEND=<link_id>,<len>
```

4. 等待模块返回 `>`
5. 发送实际文本正文
6. 等待 `SEND OK`

若任何一步失败，则本次发送结束，不阻塞小车主流程。

## 7. 主循环中的处理方式

当前主循环会持续调用：

```c
ESP8266_Poll();
```

其作用是：

- 读取 `USART3` 返回字节
- 解析连接建立与断开事件
- 为后续日志发送更新连接状态

这意味着手机断开、重连后，程序仍有机会刷新状态并继续发送新日志。

## 8. 串口与日志内容

### 8.1 串口参数

当前 `USART1` 和 `USART3` 统一配置为：

- 波特率：`115200`
- 数据位：`8`
- 停止位：`1`
- 校验位：`None`

### 8.2 手机端可见日志内容

当前手机端能够看到的主要日志包括：

- 启动横幅
- 发现车位并停车后的时间、长度和距离
- 倒车完成提示

说明：

- 当前日志内容已经精简，并改为中文
- 精简目的是减小串口与 Wi-Fi 转发对主流程实时性的影响
- 当前没有实现图像、视频或二进制数据流传输

## 9. 调试辅助模式

当前代码还保留了一个串口透传测试模式：

- 宏：`ESP8266_BRIDGE_TEST`

当该宏设为 `1` 时，程序会进入 `USART1 <-> USART3` 的简易桥接测试模式，便于先确认模块 AT 串口是否通畅。

当前正式业务版本中：

- `ESP8266_BRIDGE_TEST = 0`

因此默认运行的是“小车主流程 + 手机日志同步”模式。

## 10. 常见问题与排查

### 10.1 手机连上 Wi-Fi 但看不到日志

优先检查：

1. `P2` 是否切到 `ATK-MODULE`
2. 手机调试助手是否真的建立了 `TCP Client` 连接
3. 串口参数是否为 `115200 8N1`
4. 上电日志中 `ESP8266` 初始化是否显示 `OK`

### 10.2 串口显示初始化失败

主程序会输出类似：

```text
[ESP8266] init=FAIL, stage=..., failed_at=..., baud=...
```

此时应重点检查：

- 模块是否正常上电
- `USART3` 接口是否连接正确
- `P2` 跳线是否正确
- 模块固件是否支持标准 AT 指令

### 10.3 电脑端有日志，手机端没有

这通常说明：

- `USART1` 正常
- `ESP8266` 没有成功建链或发送失败

应重点检查：

- 是否成功连接 `192.168.4.1:8086`
- 手机端是否关闭 `HEX` 显示
- 模块是否返回 `SEND OK`

### 10.4 手机断开后程序异常

当前设计原则是：

- Wi-Fi 只是日志扩展通道
- 不能因为手机断线影响小车搜位和倒车

如果实测中出现卡顿，优先检查是否修改过 `ESP8266_SendLog(...)` 的超时与阻塞逻辑。

## 11. 验证建议

### 11.1 基础连通

- 上电后手机能搜到 `ATK-ESP8266`
- 输入密码 `12345678` 后连接成功

### 11.2 TCP 建链

- 手机调试助手能连上 `192.168.4.1:8086`
- 之后上电、发现车位、倒车完成时，手机端可收到对应文本日志

### 11.3 日志同步

建议观察以下日志是否在电脑端和手机端同时出现：

- 启动横幅
- 发现车位并停车提示
- 倒车完成提示

## 12. 当前方案结论

基于当前仓库的工程结构和探索者开发板硬件资源，当前已经实现的是：

- `USART1` 电脑端调试
- `USART3` 对接 `ATK-ESP8266`
- 最小 ESP8266 AT 驱动
- 双通道文本日志同步

因此，本项目现在的 Wi-Fi 相关功能定位应表述为“手机端日志同步显示”或“串口日志无线转发”，而不是“图像采集与 Wi-Fi 图传”。
